Audience component library

EVERY audience surface builds from @/iframe/audience by default, and that default is ENFORCED (AHAM-867): a new / rebuilt slide that hand-rolls the tappable answer row instead of AnswerOptionList fails the build (the answer-option ratchet in audience-library-detector.mjs). The qualifier is PURPOSE, not taste — a slide with no answer options does not import AnswerOption; a slide that needs a tappable row does not hand-roll one.

The library is not a style preference, it is where six guarantees are implemented once: deck-tracking ink, the frosted surface that survives a photographic deck, the 44px touch floor, the submission lock across an iframe remount, host-delegated image upload, and the deck font on a <button>. A hand-rolled control re-opens all six, and every one of them has already cost this repo review rounds (AHA-136, AHA-148, AHAM-433).

AnswerOptionList

Answers

The whole answer block: rows, single or multiple selection, the 8px thumb-safety gap (fixed, no prop), optional live counts, and the quiz reveal.

Use when
A MULTIPLE-CHOICE question (trac nghiem): a fixed set of predefined answers the participant picks from — one of them, or several with selection-mode="multiple". This is the default answer surface and covers nearly every quiz and poll; pass options, v-model, ink and palette and it carries the rest.
Not for
Anything the participant composes or positions rather than picks: free text, a scale (ScaleSlider), a drawing, an image. Also not a set of filters or tags they toggle without submitting — short inline toggles are Chip.

Replaces a hand-built tappable answer row — a tappable row carries the submission lock, the deck ink, the frosted surface and accent-by-position — hand-rolling the row re-opens all four

AnswerOption

Answers

One tappable answer row, driven entirely by a state object rather than by working its own state out.

Use when
The rare answer screen that is NOT a plain list — rows split across columns, interleaved with other content, or laid out on a board. Pair it with answerOptionState().
Not for
An ordinary list of options. AnswerOptionList already repeats this and owns the gap, the selection mode and the counts; using the row directly means re-implementing those.

The row itself, driven straight from answerOptionState(). Shown answered-and-revealed — the state with the most moving parts: a tick or cross on every row, the participant's own wrong pick carrying the incorrect tone, and the rows they did not pick muted.

DraggableOptions

Input

A reorderable list — "put the options in the correct order". Each row wears the same frosted surface and ink edge as AnswerOption, plus a live ordinal badge; the participant reorders by dragging a row or with its up/down buttons. v-model is the ordered id array. An option's imageUrl is shown IN FULL (contain, never cropped).

Use when
The answer IS an ordering — ranking, sequencing, "sort these". The model you submit is the order itself, not a pick.
Not for
Choosing option(s) from a set — that is AnswerOptionList (single or multiple). Ordering is a different answer shape, so a slide that only needs a pick does not reach for this.

Drag a row with the grip, or reorder from the keyboard with the up/down buttons — the ordinal badges renumber live either way. Two options carry an image, shown in full (contained). v-model is the ordered id array.

Input

Input

A single-line text field: the themed Ant Input (size large) with a FIXED white fill + Deep Space ink that does not track the deck, and an optional Ant Form.Item label above it that DOES track the deck ink.

Use when
The participant types one short line — a name, a word, a short answer. Pass ink (the deck's slideProps.textColour) so the label reads on a light deck and a dark one; the field stays white either way.
Not for
A number (InputNumber, which adds steppers and a numeric model), a long free-text answer (TextArea), or a pick from a fixed set (Select / AnswerOptionList).

Replaces a hand-built <input> — the themed Ant primitive gives a FIXED white fill + Deep Space ink, the optional deck-tracking Form.Item label, and the 56px/16px sizing with resting/hover/focus borders from ahaSlidesAudienceTheme — a hand-rolled single-line input re-opens all of that (wrong height, no deck-tracking label, contrast bugs).

The themed single-line field — a FIXED white fill + Deep Space ink on any deck, with the label alone tracking the deck. Opt into the in-field counter with :show-count + :maxlength.

TextArea

Input

A multi-line text field: the themed Ant Input.TextArea (size large) with a FIXED white fill + Deep Space ink that does not track the deck, and an optional Ant Form.Item label above it that DOES track the deck ink.

Use when
The participant writes a longer, free-form answer — feedback, an open question, a few sentences. Pass ink (the deck's slideProps.textColour) so the label reads on any deck; the field stays white.
Not for
A single short line (Input), a number (InputNumber), or a pick from a fixed set (Select / AnswerOptionList).

Replaces a hand-built <textarea> — the themed Ant primitive gives the multiline sizing, a FIXED white fill + Deep Space ink, the optional deck-tracking Form.Item label, and the resting/hover/focus borders from ahaSlidesAudienceTheme — a hand-rolled textarea re-opens all of that (wrong sizing, no deck-tracking label, contrast bugs).

The multiline sibling of Input, with the same fixed white field and deck-tracking label. Shown with the in-field characters-left counter (:show-count + :maxlength).

InputNumber

Input

A numeric field: the themed Ant InputNumber (size large) with up/down steppers, a numeric v-model, a FIXED white fill + Deep Space ink that does not track the deck, and an optional Ant Form.Item label above it that DOES track the deck ink.

Use when
The participant enters a NUMBER — a quantity, a count, a score, an age. Pass ink (the deck's slideProps.textColour) so the label reads on any deck; the field stays white.
Not for
Free text (Input / TextArea) or a pick from a fixed set (Select). A number bounded to a small range the participant nudges rather than types is a ScaleSlider.

Replaces a hand-built <input type="number"> — the themed Ant primitive gives the numeric model + steppers, a FIXED white fill + Deep Space ink, the optional deck-tracking Form.Item label, and the 56px/16px sizing with resting/hover/focus borders from ahaSlidesAudienceTheme — a hand-rolled numeric input re-opens all of that (wrong height, no deck-tracking label, contrast bugs).

The numeric field with steppers — same fixed white fill and deck-tracking label as Input. The model is a number (undefined when cleared).

Select

Input

A dropdown: the themed Ant Select (size large) whose closed field has a FIXED white fill + Deep Space ink that does not track the deck, and an optional Ant Form.Item label above it that DOES track the deck ink.

Use when
The participant picks ONE value from a longer or space-constrained list where showing every option as a row would be too much — a country, a category, a long enumerated set. Pass ink (the deck's slideProps.textColour) so the label reads on any deck.
Not for
A short set of predefined answers to a question — that is AnswerOptionList, which carries the 44px row target and the reveal states. Free text is Input / TextArea; a number is InputNumber.

Replaces a hand-built <select> — the themed Ant primitive gives the dropdown-selector fill on .ant-select-selector as a FIXED white with Deep Space ink, the optional deck-tracking Form.Item label, and the 56px/16px sizing with resting/hover/focus borders from ahaSlidesAudienceTheme — a hand-rolled select re-opens all of that (wrong height, no deck-tracking label, contrast bugs).

The themed dropdown — fixed white selector, deck-tracking label. Options come from the :options prop (a disabled option is shown); callers needing groups pass their own <SelectOption>s in the slot.

Timer

Feedback

A countdown: a bar that drains as the time runs out, with the clock beside it. One CSS animation off an absolute endsAt, never a rAF loop.

Use when
The question is time-limited and the participant needs to see how long is left. Pass the host's absolute end instant, not a duration.
Not for
A bare (mm:ss) badge with no bar — that is the native CountDownTimer shape and this library has no component for it; build the text and use formatClock(). Also not a progress bar for anything that is not time.

Replaces a hand-built countdown — a countdown driven from a rAF loop or a per-tick counter drifts on a backgrounded tab and runs the compositor for the length of the question — Timer is one CSS animation off an absolute end instant
